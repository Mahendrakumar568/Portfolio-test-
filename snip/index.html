fcfs.c
#include <stdio.h>

int main() {
    int n, i;
    int bt[20], wt[20], tat[20];
    float avg_wt = 0, avg_tat = 0;

    printf("Enter number of processes: ");
    scanf("%d", &n);

    printf("Enter Burst Time for each process:\n");
    for (i = 0; i < n; i++) {
        printf("P%d: ", i + 1);
        scanf("%d", &bt[i]);
    }

    // First process has 0 waiting time (assuming arrival time = 0)
    wt[0] = 0;
    for (i = 1; i < n; i++) {
        wt[i] = wt[i - 1] + bt[i - 1];
    }

    printf("\nProcess\tBurst Time\tWaiting Time\tTurnaround Time\n");
    for (i = 0; i < n; i++) {
        tat[i] = bt[i] + wt[i];
        avg_wt += wt[i];
        avg_tat += tat[i];
        printf("P%d\t%d\t\t%d\t\t%d\n", i + 1, bt[i], wt[i], tat[i]);
    }

    printf("\nAverage Waiting Time: %.2f", avg_wt / n);
    printf("\nAverage Turnaround Time: %.2f\n", avg_tat / n);

    return 0;
}

FCFS (First-Come, First-Served) CPU Scheduling

Theory and viva notes, Operating Systems Lab (CSE 301L)

1. Core Definition & Working Principle

  • What it is: FCFS is the simplest non-preemptive CPU scheduling algorithm where processes are executed strictly in the exact order they arrive in the Ready Queue.
  • Data Structure Used: Managed using a standard FIFO (First-In, First-Out) Queue. When a process enters the ready queue, its Process Control Block (PCB) is linked to the tail, and when the CPU becomes free, it is allocated to the process at the head.
  • Non-Preemptive Nature: Once the CPU is allocated to a process, it keeps the CPU until it either terminates or switches to a waiting state (for I/O). It cannot be interrupted midway by a newly arrived shorter process.

2. Key Scheduling Terms & Formulas

Examiners almost always ask you to define these four terms from your output table:

  • Burst Time (BT): The total time required by a process for its execution on the CPU.
  • Completion Time (CT): The exact timestamp when a process finishes its execution.
  • Turnaround Time (TAT): The total time spent by a process in the system (from arrival to completion).
    TAT = Completion Time − Arrival Time   (or BT + WT)
  • Waiting Time (WT): The total time a process spends waiting in the ready queue before getting the CPU.
    WT = Turnaround Time − Burst Time

3. Advantages & Disadvantages

Advantages:

  • Easy to understand, implement, and code using a simple FIFO queue.
  • No Starvation: Every process eventually gets executed because there is no priority skipping.

Disadvantages:

  • Convoy Effect: If a long CPU-bound process arrives first, all shorter processes behind it must wait until it finishes, leading to poor CPU and I/O device utilization.
  • High Average Waiting Time: Because burst times are ignored, average waiting time is often much higher than in Shortest Job First (SJF) or Round Robin (RR).
  • Not suitable for interactive/time-sharing systems: Since it is non-preemptive, users cannot get quick response times.

4. Rapid-Fire Viva Q&A (Likely Examiner Questions)

Q: Is FCFS preemptive or non-preemptive?
A: Strictly non-preemptive.
Q: What is the Convoy Effect?
A: A phenomenon where multiple short processes get held up behind one long CPU-intensive process, causing low throughput and high average waiting time.
Q: Which scheduling criteria does FCFS optimize, if any?
A: It minimizes scheduling overhead (very few context switches) and guarantees zero starvation, though it does not optimize waiting time or response time.
Q: What happens in your code if all processes arrive at t = 0?
A: They execute in the input order (P1, P2, P3, …), so P1’s waiting time is 0, and each subsequent process’s waiting time is the sum of the burst times of all preceding processes.
